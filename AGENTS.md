# Работа в codex-awake

## Ветки и pull requests

Все изменения публиковать в отдельной ветке `codex/<task>` и оформлять pull request в `main` для ревью пользователя. Прямой push изменений в `main` запрещён. Исключение допускается только по явному запросу пользователя на конкретное действие, например откат коммита.

После создания PR передать пользователю ссылку. Не выполнять merge и не включать auto-merge без явного одобрения пользователя для этого PR. Разрешение сделать commit, push или открыть PR не означает разрешение на слияние.

## Источник спецификаций

Начинай с [docs/modules/index.md](docs/modules/index.md) и спецификации изменяемого модуля. В `docs/` хранится только `modules/`.

Для написания и изменения спецификаций используй [writing-spec из essay-platform](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/.agents/skills/writing-spec/SKILL.md). Прочитай скилл перед работой; не подменяй его общим архитектурным обзором. Скилл применяется из источника, локальная копия в репозиторий не установлена.

## Формат

- `README.md` модуля: назначение, границы ответственности, зависимости.
- `settings.md`: настройки с типом, обязательностью и значением по умолчанию.
- `caches.md`: кэши, ключи, значения, TTL, размер, формирование и инвалидация; отсутствие кэшей указывать явно.
- `jobs/<operation>.md`: отдельный документ на фоновую операцию с разделами скилла.
- `operations/<operation>.md`: контракт внутренней операции, пока внешний протокол не выбран. Использовать разделы метода из скилла без выдуманного HTTP/gRPC endpoint.
- `queue/`: контракт очереди effectum, payload задач, выполнение, повторы и восстановление.
- `database/`: хранение прикладного состояния в SQLite, физические схемы и миграции после их определения. Внутренними таблицами effectum управляет библиотека; не изменять их напрямую.
- `database/schema.dbml` и производный SVG нужны при наличии PostgreSQL; в выбранном стеке PostgreSQL отсутствует. Не создавать фиктивные `http/`, `grpc/` и SQL-схемы.

Текст спецификации должен задавать поведение нормативно. Каждый алгоритм определяет чтения, записи, поля, ветви, результаты и порядок внешних эффектов. Не помещать в спецификации исследования, примеры, рекомендации и тест-кейсы. Не объявлять неполный алгоритм готовым к реализации.

## Решения и изменения

Утверждены Rust backend + effectum с хранением очереди в файловой SQLite (решение пользователя от 2026-10-27, заменяет NATS JetStream) и первый сценарий: наблюдать уже запущенный локальный процесс и доставлять факт завершения в исходный чат Codex. Получение exit code и логов не входит в первый сценарий. Отдельный брокер NATS и JetStream KV не используются.

Доставлять сообщение прямым вызовом App Server RPC `thread/queue/add` на сервере, обслуживающем исходный чат Desktop (решение пользователя от 2026-10-27). Использовать JSON-RPC через локальный TCP WebSocket на loopback-адресе (решение пользователя от 2026-10-28); Desktop и backend подключаются к одному серверу. Не запускать дополнительный App Server для записи в общую очередь. Внутренний IPC Desktop не подменяет выбранный RPC. Конкретный общий endpoint и способ настройки Desktop, физическая схема прикладного состояния и политика effectum ещё не определены. Подтверждение постановки в очередь не считать подтверждением запуска или завершения хода.

Не выбирать самостоятельно отсутствующие решения, меняющие внешнее поведение, сохраняемые данные или гарантии доставки. Задавать конкретный вопрос и продолжать независимую часть работы. Незавершённые контракты отмечать в индексе и соответствующем файле; не заполнять пробелы скрытыми defaults.

Изменять спецификацию вместе с поведением кода в одной задаче и публикации. Перед публикацией проверить локальные ссылки, обязательные разделы, согласованность контрактов и `git diff --check`. Самопроверку не называть независимым ревью.

Ожидание не вызывает модель. Завершение процесса не равно успеху команды; приём сообщения Codex не равен завершению поручения. Не повторять неоднозначную доставку вслепую. Не добавлять в Git credentials, runtime-данные, переписки и логи пользователя. Сохранять изменения вне задачи.
