# Источники событий

Статус: проект интерфейса адаптеров. Первый CI-провайдер пока не выбран.

## Общий контракт

Адаптер получает точный источник и идентификатор запуска, наблюдает его и возвращает финальный результат. Он сохраняет различие между успехом, неуспехом и отменой задачи; нормализацию статусов конкретного провайдера нужно специфицировать отдельно.

Адаптер сообщает свои возможности: push, replay, получение текущего статуса, позиция возобновления. Он не выбирает чат, не исполняет инструкции из лога и не повторяет запуск наблюдаемой задачи.

## CI

Предпочтителен существующий поток событий с возможностью возобновления. Webhook требует доступного адреса на Mac или отдельно выбранного relay; localhost автоматически не становится доступен удалённому CI. Внешний relay и его хостинг не входят в согласованный стек.

После разрыва соединения сначала выполнить replay, если он доступен. Если истории нет, сверить статус конкретного запуска через API. Если недоступны оба механизма, показать разрыв наблюдения; не обещать восстановление пропущенного события.

Если источник поддерживает только polling, частоту и лимиты задаёт обычный код адаптера. Такой режим должен быть явно обозначен пользователю. Для webhook перед принятием нужны проверка подлинности, защита от повторов и ограничение размера; конкретная схема зависит от провайдера.

## Локальные процессы

Обычное завершение дочернего процесса может наблюдаться средствами ОС. Выходной код и ограниченный вывод становятся результатом. После падения родительской службы одного PID недостаточно для надёжного восстановления результата: PID может переиспользоваться, exit status может быть недоступен.

Первая реализация должна явно определить потерю наблюдения и политику для дерева процессов. Повторное исполнение команды после рестарта не допускается автоматически. Устойчивость очереди сообщений не означает устойчивость исполнения процесса.
