# Хранение SQLite

Статус: файловое хранение очереди effectum в SQLite принято; физическая схема прикладного состояния не завершена, S1.

## Ресурсы

- Внутреннее хранилище задач effectum: создание и изменение задач выполнять через API библиотеки. Не изменять её внутренние таблицы напрямую.
- [Регистрации и журнал доставки](state.md): определить отдельный прикладной контракт схемы и миграций до реализации операций.

Не использовать in-memory SQLite или временный каталог для устойчивой очереди. Перезапуск backend должен открывать сохранённую очередь. Недоступность прежнего файла не подменять успешным открытием пустой базы.

Расположение прикладных таблиц в том же или другом SQLite-файле ещё не определено. Не обещать атомарность изменения этих таблиц и добавления job до выбора поддерживаемой библиотекой границы транзакции.

Физическую схему и миграции публиковать после определения таблиц. PostgreSQL DBML и SVG в выбранном стеке не применяются.
