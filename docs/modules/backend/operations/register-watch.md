# Регистрация ожидания

Статус: неполный контракт; S1, S4 и S5. Wire format, коды ошибок и алгоритм записи не утверждены.

## Метод

Внутренняя операция регистрации. Внешний CLI/IPC/API ещё не определён.

## Описание

Связать существующий процесс с исходным чатом и разрешённым продолжением.

## Ресурсы

- [Состояние регистрации](../database/state.md).
- [Привязка процесса](../../process-watch/operations/attach-process.md).

## Входные параметры

Таблица задаёт логические входы, а не готовую схему сериализации.

| Название | Тип | Обязательность | Описание |
|---|---|---|---|
| `registration_key` | Строка | Да | Идемпотентность запроса регистрации |
| `pid` | Положительное целое | Да | PID уже запущенного процесса на локальной машине |
| `thread_id` | Строка | Да | Исходный чат Codex |
| `continuation` | Строка | Да | Заранее разрешённая инструкция после завершения процесса |

## Выходные параметры

| Название | Тип | Обязательность | Описание |
|---|---|---|---|
| `watch_id` | Строка | При успехе | Идентификатор устойчиво сохранённого ожидания |

## Результат в случае успеха

Вернуть идентификатор сохранённой регистрации. Успех не должен означать, что процесс всё ещё работает или что Codex уже получил уведомление.

## Результат в случае ошибки

Не возвращать неподтверждённую регистрацию как успешную. Потерю подтверждения хранения отличать от доказанного отсутствия записи; повтор должен использовать прежний `registration_key`.

## Алгоритм работы

Завершение алгоритма приостановлено до определения физической схемы и атомарной границы регистрации относительно подписки на процесс.

Зафиксировать следующие ограничения порядка:

1. Разрешить PID в идентичность конкретного экземпляра процесса через `attach-process`; не использовать один PID как устойчивую идентичность.
2. Сохранить привязку идентичности к `thread_id` и `continuation` до успешного ответа.
3. При повторе `registration_key` с теми же полями вернуть ранее сохранённый `watch_id`; несовпадающие поля не перезаписывать.
4. Обработать завершение между привязкой и фиксацией без привязки к новому процессу с тем же PID. Точный механизм определить в S4.

Не считать эти ограничения полным алгоритмом чтений, записей и внешних вызовов.

## Ошибки

До завершения контракта определить коды, статус и message для некорректного ввода, отсутствующего/недоступного процесса, конфликта регистрации и неопределённого результата записи. Не назначать произвольные HTTP/gRPC статусы внутренней операции.
