# Задача доставки события завершения

Статус: неполная спецификация payload и постановки job, S1 и S2.

## Назначение

Сохранять факт завершения наблюдаемого процесса в очереди effectum до обработки доставки. Повторная постановка того же факта должна сохранять идентичность события; не считать её новым завершением.

## Содержание

Формат сериализации и физические имена полей не определены. Задача должна содержать идентификатор события, ссылку на регистрацию, идентичность наблюдавшегося экземпляра процесса и факт завершения. Поля exit code, stdout и stderr не включать в контракт первой версии.

Исчезновение процесса после перерыва в наблюдении не подменять подтверждённым уведомлением ОС. Политику такого случая определить в S4 до описания соответствующего типа события.

## Постановка в очередь

Использовать API добавления job effectum. Не считать событие сохранённым до успешного завершения операции согласно контракту выбранной версии библиотеки. При неизвестном результате записи не формировать новый идентификатор для повторной постановки.

В S1 и S2 определить соответствие идентификатора события ID job, обработку уже существующей job и сверку после неизвестного результата. Не предполагать, что повтор добавления идентичного ID автоматически означает успешную идемпотентную регистрацию.

## Незавершённые параметры

Определить тип job, payload и его версию, максимальный размер, лимит очереди и поведение при заполнении диска. Не удалять необработанные задачи для освобождения места без явно определённого результата для пользователя.

Устойчивость при падении процесса и отключении питания определить отдельно с политикой синхронизации SQLite. Устойчивый промежуток между событием ОС и записью job ещё не специфицирован.
