# Worker effectum

Статус: библиотека выбрана; параметры worker, повторов и восстановления не определены, S2.

## Назначение

Выполнять job доставки в Rust backend и учитывать её результат через API effectum. Не использовать отдельный NATS consumer или broker ack/NAK.

## Выполнение и завершение

В начале каждой попытки читать прикладное состояние доставки до обращения к Codex. Уже принятую доставку повторно не отправлять. Не завершать job как успешно обработанную до устойчивой записи соответствующего результата доставки.

Неоднозначную попытку не повторять только потому, что effectum заново запустил job. Состояние `delivery_unknown` должно блокировать новый внешний вызов до сверки или решения пользователя. При исчерпании повторов сохранять видимую причину остановки.

В S2 определить отображение прикладных результатов на успешное завершение, ошибку и окончательное прекращение job. Не возвращать из handler обычную повторяемую ошибку для неоднозначной доставки без механизма, исключающего повторный вызов Codex.

## Восстановление

Effectum предусматривает повтор задач, оставшихся выполняющимися при перезапуске, сразу или с задержкой ([JobRecoveryBehavior](https://docs.rs/effectum/latest/effectum/enum.JobRecoveryBehavior.html)). Перед запуском восстановленных обработчиков backend должен исключить повтор внешних отправок с неизвестным исходом.

Выбор политики восстановления библиотеки не заменяет журнал доставки. Порядок запуска worker относительно сверки прикладного состояния определить в S1 и S2.

## Незавершённые параметры

Закрепить версию effectum, тип обработчика job, параллелизм, timeout, число попыток, backoff, JobRecoveryBehavior и хранение результатов. Повторы задач должна планировать effectum; не добавлять второй независимый планировщик тех же повторов в backend.
