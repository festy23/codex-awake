# Очередь effectum

Статус: Rust backend + effectum с файловой SQLite приняты пользователем 2026-10-27 вместо NATS JetStream. Параметры интеграции ещё не завершены, S1 и S2.

## Ресурсы

| Ресурс | Документ |
|---|---|
| Задача доставки факта завершения процесса | [events.md](events.md) |
| Worker, повторы и восстановление | [worker.md](worker.md) |
| Прикладное состояние | [database/state.md](../database/state.md) |

Effectum использовать как библиотеку очереди внутри Rust backend. Не запускать отдельный брокер сообщений. SQLite открывать как постоянный файл; не использовать in-memory режим для устойчивых данных.

Подтверждение сохранения job, состояние прикладной доставки и приём сообщения Codex считать разными фактами. SQLite не создаёт транзакцию с внешним интерфейсом Codex.

До реализации закрепить версию effectum, payload, идентификаторы, предел параллелизма, повторы, восстановление и сроки хранения. Автоматическое повторное исполнение job не должно обходить проверку состояния доставки.

Контракт библиотеки: [effectum](https://docs.rs/effectum/latest/effectum/). Ссылка описывает API библиотеки; проверенная версия для проекта ещё не выбрана.
