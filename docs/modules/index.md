# Спецификации модулей

## Область

Использовать Rust backend и NATS JetStream. В первом сценарии наблюдать уже запущенный локальный процесс и доставлять факт завершения в исходный чат Codex Desktop. Результат команды Codex проверяет по заранее заданной инструкции. Не получать exit code, stdout и stderr в рамках этого сценария. Не запускать и не перезапускать наблюдаемую команду.

Ожидание и восстановление службы не должны вызывать модель. CI-интеграции не входят в первую специфицируемую версию. Начальная платформа — macOS; платформенные контракты Linux и Windows не определены.

## Модули

| Модуль | Ответственность | Контракты |
|---|---|---|
| [Backend](backend/README.md) | Регистрации, сохранение событий и доставка | [Регистрация](backend/operations/register-watch.md), [отмена](backend/operations/cancel-watch.md), [доставка](backend/jobs/deliver-event.md), [восстановление](backend/jobs/recover-state.md) |
| [Process watch](process-watch/README.md) | Идентификация и наблюдение уже запущенного процесса | [Привязка процесса](process-watch/operations/attach-process.md), [ожидание завершения](process-watch/jobs/observe-process.md) |
| [Codex delivery](codex-delivery/README.md) | Передача результата в исходный чат | [Отправка результата](codex-delivery/operations/submit-result.md) |

Это логические модули Rust-программы. Наблюдатель не выбирает чат. Транспорт Codex не управляет повторами независимо от backend.

## Статус полноты

Спецификации находятся в разработке. Документы операций выделены по формату `writing-spec`; частичные алгоритмы не считать завершёнными нормативными контрактами для реализации.

| ID | Неопределённое решение | Зависимые документы |
|---|---|---|
| S1 | Использование JetStream KV; физические ключи, сериализация и конкурентные обновления | [Хранение состояния](backend/jetstream/state.md), регистрация, отмена, восстановление |
| S2 | Stream/consumer, лимиты, retention, политика повторов и синхронизации диска | [Поток](backend/jetstream/events.md), [consumer](backend/jetstream/consumer.md), доставка |
| S3 | Доступный транспорт Desktop, receipt, busy/cold/interrupted поведение | [Отправка результата](codex-delivery/operations/submit-result.md) |
| S4 | Устойчивая идентичность процесса, гонка регистрации и обработка пропущенного завершения | [Привязка процесса](process-watch/operations/attach-process.md), наблюдение, восстановление |
| S5 | Внешний интерфейс регистрации/отмены, валидация, ошибки и настройки | [Операция регистрации](backend/operations/register-watch.md), файлы settings |

Не вводить технические значения по умолчанию для этих решений без определения их наблюдаемого поведения. Не создавать HTTP/gRPC методы до выбора соответствующего интерфейса.
