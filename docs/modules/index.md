# Спецификации модулей

## Область

Использовать Rust backend и встроенную очередь effectum с хранением в файловой SQLite. Решение пользователя от 2026-10-27 заменяет NATS JetStream; отдельный брокер и JetStream KV не использовать. Версия effectum и численные параметры ещё не закреплены. В первом сценарии наблюдать уже запущенный локальный процесс и доставлять факт завершения в исходный чат Codex Desktop. Результат команды Codex проверяет по заранее заданной инструкции. Не получать exit code, stdout и stderr в рамках этого сценария. Не запускать и не перезапускать наблюдаемую команду.

Ожидание и восстановление службы не должны вызывать модель. CI-интеграции не входят в первую специфицируемую версию. Начальная платформа — macOS; платформенные контракты Linux и Windows не определены.

Доставлять сообщение прямым RPC `thread/queue/add` в App Server, обслуживающий исходный чат Desktop. Не запускать дополнительный App Server для записи в общее хранилище очереди. Не заменять этот RPC внутренними методами IPC Desktop. Конкретный способ предоставления общего endpoint и совместимые версии определить в S3.

## Статус полноты

Спецификации находятся в разработке. Документы операций выделены по формату `writing-spec`; частичные алгоритмы не считать завершёнными нормативными контрактами для реализации.

| ID | Неопределённое решение | Зависимые документы |
|---|---|---|
| S1 | Физическая схема прикладного состояния SQLite, граница между ней и очередью effectum, конкурентные обновления | [Хранение состояния](backend/database/state.md), регистрация, отмена, восстановление |
| S2 | Версия effectum, лимиты, хранение завершённых задач, политика повторов/восстановления и синхронизации SQLite | [Задача доставки](backend/queue/events.md), [worker](backend/queue/worker.md), доставка |
| S3 | Общий endpoint Desktop для выбранного `thread/queue/add`, совместимые версии, таймауты, маппинг сообщения и receipt, busy/cold/interrupted поведение | [Отправка результата](codex-delivery/operations/submit-result.md) |
| S4 | Устойчивая идентичность процесса, гонка регистрации и обработка пропущенного завершения | [Привязка процесса](process-watch/operations/attach-process.md), наблюдение, восстановление |
| S5 | Внешний интерфейс регистрации/отмены, валидация, ошибки и настройки | [Операция регистрации](backend/operations/register-watch.md), файлы settings |

Не вводить технические значения по умолчанию для этих решений без определения их наблюдаемого поведения. Не создавать HTTP/gRPC методы до выбора соответствующего интерфейса.
