# Ожидание завершения процесса

Статус: частичный контракт; подписка и сохранение результата зависят от S1, S2 и S4.

## Описание

Дождаться факта завершения привязанного экземпляра процесса и передать его backend.

## Запуск

Успешная [привязка процесса](../operations/attach-process.md) при действующей регистрации.

## Входные параметры

| Название | Тип | Обязательность | Описание |
|---|---|---|---|
| `watch_id` | Строка | Да | Регистрация backend |
| Идентичность процесса | Структура по контракту attach-process | Да | Экземпляр, завершение которого ожидается |
| Подписка | Ресурс ОС по контракту attach-process | Да | Источник уведомления о завершении |

## Результат

Факт завершения конкретного экземпляра процесса либо ошибка наблюдения. Не добавлять предположение об успешности команды.

## Ресурсы

- Подписка ОС из `attach-process`.
- Регистрация [backend](../../backend/jetstream/state.md).
- [Поток завершений](../../backend/jetstream/events.md).

## Алгоритм работы

1. Ожидать событие ОС без вызовов модели и без периодического опроса процесса.
2. Разделять уведомление о завершении, отмену регистрации и ошибку подписки. Ошибку подписки не преобразовывать в завершение.
3. При подтверждённом завершении передать backend идентичность процесса и `watch_id`. Использовать один стабильный идентификатор события при повторе передачи того же результата.
4. Не считать передачу завершённой до подтверждения сохранения backend. Устойчивый механизм между получением события ОС и PubAck определить в S1 и S2.
5. При подтверждённой отмене освободить ресурс наблюдения, не посылая сигнал процессу.

Это ограничения алгоритма. Точные вызовы ОС, поля сообщения, порядок записи и ветви восстановления после сбоя не завершены. Событие в памяти нельзя считать восстановимым после падения backend.
