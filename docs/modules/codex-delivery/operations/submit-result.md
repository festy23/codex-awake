# Отправка результата

Статус: неполный контракт; S3. Штатная очередь Codex и `turn/start.toolOutput` остаются кандидатами, ни один не утверждён для установленного Desktop.

## Метод

Внутренняя операция `codex-delivery`. RPC/CLI и точный запрос определяются после выбора транспорта.

## Описание

Передать уведомление о завершении процесса в исходный чат и вернуть результат приёма.

## Ресурсы

Интерфейс сервера, обслуживающего нужный чат Desktop. Отдельный сервер без этого чата не является допустимой заменой адресата.

## Входные параметры

| Название | Тип | Обязательность | Описание |
|---|---|---|---|
| `delivery_id` | Строка | Да | Корреляция попытки; не предполагает поддержку идемпотентности получателем |
| `thread_id` | Строка | Да | Исходный чат |
| `continuation` | Строка | Да | Заранее разрешённая инструкция |
| Событие завершения | Структура по контракту backend | Да | [Факт завершения процесса](../../backend/queue/events.md) |

## Выходные параметры

Ответ должен различать подтверждённый приём, доказанный неприём и неизвестный исход. При подтверждённом приёме передавать доступное подтверждение транспорта. Формат receipt и классификацию конкретных ошибок определить в S3.

## Результат в случае успеха

Подтверждён приём сообщения в указанном чате. Не заявлять завершение работы агента на основании этого ответа.

## Результат в случае ошибки

Потерю ответа после возможного приёма классифицировать как неизвестный исход, а не доказанный неприём. Не менять адресата и не выполнять скрытую повторную отправку.

## Алгоритм работы

Точный алгоритм внешнего вызова приостановлен до S3: нужны запрос, timeout, ответ и поведение для busy/cold/interrupted чатов.

Для выбранного транспорта соблюдать следующие ограничения:

1. Использовать только переданный `thread_id`.
2. Отделять данные события от инструкции `continuation`; данные не расширяют разрешённые действия пользователя.
3. Выполнить одну попытку передачи в рамках вызова операции. Политику автоматических повторов передать backend.
4. Подтверждённый приём вернуть с receipt; возможный приём без подтверждения вернуть как неизвестный исход.
5. Доказанный неприём вернуть с причиной, позволяющей backend различить постоянную и временную ошибку. Классификацию для конкретного транспорта определить до реализации.

Не считать код завершения CLI достаточным подтверждением без установленного контракта команды. Не писать напрямую в внутреннюю базу Desktop.

## Ошибки

Для выбранного транспорта определить коды, статусы и message для недоступного сервера, недоступного чата, отказа в доступе, несовместимой версии, превышения размера и неопределённого результата. Не назначать эти коды до выбора интерфейса.
