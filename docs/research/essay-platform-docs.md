# Как устроена документация essay-platform

Исследовано 2026-10-26. Источник: [photorus/essay-platform](https://github.com/photorus/essay-platform/tree/9dc96179ab36d36eb05a45e16d120f625402c42a), commit `9dc96179ab36d36eb05a45e16d120f625402c42a`. Репозиторий клонирован отдельно для чтения.

## Организация

[AGENTS.md](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/AGENTS.md) служит маршрутизатором к документации, скиллам и процедурам. Он закрепляет обновление документации вместе с кодом и проверку соответствия финальному изменению.

[docs/index.md](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/docs/index.md) разделяет прикладные модули и инфраструктурную спецификацию. В модуле есть README и документы по операциям, настройкам, данным и интеграциям. Инфраструктура описывает окружения и размещение, не переопределяя прикладные контракты. ADR сохраняют основания решений отдельно.

## Скиллы

| Скилл | Задача | Полезный принцип |
|---|---|---|
| [writing-spec](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/.agents/skills/writing-spec/SKILL.md) | Создание формальной спецификации модуля | Алгоритм задаёт поля, ресурсы, ветви, ошибки и границы внешних эффектов; неизвестные решения нельзя маскировать default-значениями |
| [reviewing-spec](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/.agents/skills/reviewing-spec/SKILL.md) | Проверка спецификации без её изменения | Проверять реализуемость, согласованность, достижимые сбои и лишние механизмы; замечания привязывать к точному месту |
| [humanizing-spec](https://github.com/photorus/essay-platform/blob/9dc96179ab36d36eb05a45e16d120f625402c42a/.agents/skills/humanizing-spec/SKILL.md) | Редакторский проход | Упрощать язык, сохраняя нормативный смысл, порядок, условия и числа |

Это три разных прохода: написать контракт, проверить содержание, улучшить читаемость. Самопроверка автора не выдаётся за независимое ревью.

## Что адаптировано для codex-awake

Короткий AGENTS-навигатор, индекс docs, владение правилами по разделам, Docs as Code и описание отказов приняты как подход к документации. Правила написаны заново в [нашем стандарте](../standards/documentation.md).

Не переносим Tracker, Kubernetes, облачные окружения, PostgreSQL DBML и сервисную структуру essay-platform: они относятся к другому продукту. Для нас важнее stream/consumer, состояние доставки, локальные процессы и контракт Codex. Модули будут логическими частями одной Rust-программы.

Скиллы изучены как материал для организации работы, не установлены и не скопированы. Для текущего этапа их полезные принципы оформлены в документации; отдельный локальный скилл можно создать, если потребуется повторяемый инструментальный workflow.
