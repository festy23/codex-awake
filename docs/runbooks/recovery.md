# Диагностика и восстановление

Статус: проект процедуры; CLI и команды управления ещё не реализованы. Это не инструкция для существующей установки.

## Событие не дошло до чата

1. Найти ожидание по ID и проверить источник, запуск и целевой чат.
2. Проверить доступность брокера, службы и сохранённое состояние. Не очищать очередь и не регистрировать то же ожидание с новым ключом ради восстановления.
3. Если результата нет, проверить источник и возможность replay/сверки статуса. Отделить продолжающуюся задачу от потерянного наблюдения.
4. Если результат сохранён, проверить состояние доставки по [жизненному циклу](../modules/backend/lifecycle.md).
5. Для `accepted` проверить продолжение чата отдельно: приём не равен завершению работы агента.
6. Для `delivery_unknown` искать подтверждение транспорта. При отсутствии доказательства не повторять автоматически; показать пользователю риск повторного запуска хода.
7. Для `needs_attention` исправить конкретную причину и определить допустимость повтора.

## Служба падает или не запускается

Проверить ограниченные технические логи, версию бинарника, доступ к каталогу данных и состояние NATS. Отдельно определить, является ли остановка намеренной. Восстановление не должно менять настройки Desktop или запускать повторно пользовательскую команду.

## Сохранение данных

Удаление runtime-каталога — потеря ожиданий и истории доставки. Backup/restore и миграции должны быть описаны для выбранной схемы перед первой установкой. Восстановление старого snapshot может вернуть уже обработанные сообщения; после restore нужна сверка внешних доставок, а не массовый retry.
