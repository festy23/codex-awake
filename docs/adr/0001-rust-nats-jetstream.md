# ADR-0001: Rust backend и NATS JetStream

Статус: принято пользователем 2026-10-26.

## Контекст

Нужно продолжать исходный чат Codex Desktop по завершении внешней задачи без обращений к модели во время ожидания. Локальное состояние должно переживать падение службы. Пользователь не планирует размещать сервис на VM; первая целевая платформа — macOS.

## Решение

Используем собственный backend на Rust и NATS JetStream как готовый механизм потоков и очереди сообщений. Система работает локально. В архитектуре учитываем последующую поддержку Linux и Windows.

Pueue, PostgreSQL/pg-boss, собственная SQLite-очередь и перенос Node.js-ядра agent-wake не используются в выбранном варианте. Kandler agent-wake остаётся источником исследования.

## Последствия

Потребуются Rust-программа и локальный `nats-server`, их установка, управление версиями и восстановление после падения. Наш код отвечает за адаптеры CI, регистрацию ожиданий, адресацию чатов и обработку результата доставки. Брокер не выполняет команды и не определяет момент запуска модели.

Гарантия доставки брокером не равна однократному выполнению действия в Codex. Разрыв между внешним приёмом и локальной записью требует отдельной политики.

## Что этим решением не утверждено

Конкретный транспорт Desktop, первый CI-провайдер, KV-схема, настройки stream/consumer, численные лимиты и формат установки остаются проектными решениями. Их статус ведётся в [реестре открытых решений](../architecture/open-decisions.md).
